Security model

Strong primitives. Tiny footprint.

Bytarith v1 uses your browser's native Web Crypto API. Every encryption gets a fresh random salt and IV, and AES-GCM authenticates the result so tampering or an incorrect key is rejected.

Local by design

No encryption API, account, database, analytics pipeline, or server-side key handling. The cryptographic work happens in this tab.

Portable output

Every result begins with BY1., followed by a URL-safe encoded payload containing only the data required for decryption.

03

Random short keys

The generator creates 16-character keys from a 32-symbol alphabet, providing 80 bits of random key entropy while staying practical to share.

The BY1 envelope

A recognizable format with room to evolve.

BY1 stores the KDF work factor, random salt, random IV, and authenticated ciphertext in one compact payload. The secret key is never embedded in the string.

Use generated keys for real privacy.

A strong cipher cannot rescue a predictable password. Bytarith slows password guessing with PBKDF2, but a randomly generated key is still substantially safer than a short word, date, PIN, or reused password.
